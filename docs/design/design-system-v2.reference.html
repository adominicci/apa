Tesina Design System · v2

One badge, one chip, one modal.

v1 gave the app shared tokens, buttons, fields and modal chrome. What it never defined was the small stuff: badges, pills, tags, counts and filter chips were each re-invented inside the component that needed them. Five definitions, five shapes, five ways of spending the accent color. This is the missing layer, plus the two open questions v1 left in the button and modal APIs.

Each semantic color ships with a -soft wash. A badge or status surface uses the wash as background and the solid as text — never the solid as a fill, which is reserved for the primary button and the segmented control's selected item.

The rule that fixes it

Shape says whether you can click it. Color says how urgent it is.

v1's small components drifted because nothing said which shape or color meant what, so each author picked. Two rules close that gap, and everything below follows from them.

Squared is information

Badges and counts get --r-xs. They are labels on the content, not controls.

Pill is a control

Chips, the dock and its buttons get --r-pill. If it's fully round, pressing it does something.

Neutral Accent Warn Danger

Color encodes urgency, not category. A reference's type and an essay's language are categories: they are neutral. "Uncited" and "Duplicate" are things to fix: they are warm.

Accent is the app's only live color and it is scarce on purpose — it marks the current selection and the primary action. A badge earns accent only when it names what the user is acting on right now.

Component · new

Chip

A filter you toggle. Always a <button>, always in a wrapping flex row with gap: var(--sp-2). Selected reads aria-pressed="true"; the existing .on class is accepted too, so no component logic changes.

States

Hover moves the border and text only. The wash is reserved for selected, so hovering never previews selection.

Chip vs. segmented control

Chips narrow a list and any number can be off. The segmented control picks exactly one mode, and keeps the solid accent fill. Two jobs, two shapes, two weights of color.

The document · locked layer

APA 7 is not a style choice. It is the specification.

Everything above this line is chrome, and chrome is ours to design. The paper sheet is not. Its geometry, type sizes, spacing and indents are fixed by the APA Publication Manual (7th ed.), and the app exists to guarantee them — a student should never have to check. So this layer has one rule that outranks every other rule in this document:

No chrome token, component or aesthetic preference may change a measurement inside the paper sheet. If a value is prescribed by APA, it is not a design decision.

Double, throughout

The 816px coordinate system never changes. The canvas may scale the whole stack to fit a narrow window, but wrapping and pagination are computed in page units, so what you see on screen breaks where the printed page breaks.

The seven permitted fonts

Size is bound to family, not chosen separately: picking Georgia sets 11pt, picking Times sets 12pt. There is no font-size control in the document, and there should never be one — that is the single most common way a paper falls out of compliance.

APA_FONTS in model/fonts.ts is the single source of truth for screen and preview; the DOCX exporter keeps a parallel table that must be changed in the same commit.

Headings — five levels, all at document size
Level 1 Is Centered and Bold
Text begins as a new paragraph.
Level 2 Is Flush Left and Bold
Text begins as a new paragraph.
Level 3 Is Flush Left, Bold Italic
Text begins as a new paragraph.
Level 4 Is Indented, Bold, and Ends With a Period. Text continues on the same line.
Level 5 Is Indented, Bold Italic, and Ends With a Period. Text continues on the same line.

No heading changes size, and none is underlined or set in caps. Levels 4 and 5 are run-in: the app marks a heading as run-in only when a paragraph actually follows it, appends the terminal period if the author did not type one, and leaves both nodes independently editable. Levels are Title Case — that is the one APA heading rule the live check does not currently verify.

The document keeps its own palette

.apa-editor pins pre-v1 hex values for --fg, --paper and the rest, and restates the derived tokens rather than inheriting them. Retuning the chrome palette therefore cannot restyle the sheet.

The print preview's sheet is deliberately theme-independent: the export CSS hardcodes near-black ink, so following --paper in dark mode would darken the page while the text stayed black.

Editing affordances that must never print
  • Dashed ghost gridlines inside tables
  • Citation chips, set in the chrome font at 0.82em
  • The APA-check tint and the overflow outlines
  • The pencil buttons on tables, figures and equations
  • The "no references yet" message on the reference page

Each is chrome living inside the document. The preview and DOCX export render from their own stylesheets, which is what keeps them off the page — and the reason any new in-document affordance has to be added there as an exclusion in the same commit.

Two things to watch

Scope. .badge, .chip and .btn-quiet are global, like .btn. The APA paper sheet uses cover-form-* and the dock uses fm-*, so neither is reachable — but a Svelte component's own <style> block still outranks these rules, so the local definition has to be deleted, not just left unused.

Tone, not shape. The mechanical part is the class rename. The judgement part is deciding, per badge, whether it classifies (neutral) or needs fixing (warm). That decision is the whole point — a global find-and-replace to .badge-accent would reproduce the problem in new syntax.
