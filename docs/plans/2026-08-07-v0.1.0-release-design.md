# Tesina v0.1.0 Release Design

## Objective

Ship an academically trustworthy first release for university students as a
public, universal macOS DMG. The supported paper contract is APA 7 student
papers in English or Spanish. Windows and Linux packages are built after merges
to `main` as maintainer-only CI artifacts, but are not advertised or supported
in v0.1.0.

## Product boundary

v0.1.0 exposes only student papers. Professional-paper controls and templates
are hidden until their title page, running head, and author-note behavior can be
completed without compromising the student release. The persisted
`PaperVariant` type remains additive and schema version stays at `2`; existing
pre-release professional documents are normalized to student mode when opened,
without deleting dormant title-page text.

Student title pages support individual and group assignments through two
deterministic affiliation rules:

1. One affiliation applies to every author.
2. When author and affiliation counts match, each author maps to the
   affiliation on the same line. Repeated affiliation names are deduplicated
   before numbering.

Any other combination is ambiguous. Draft editing remains available, but DOCX
export is blocked with a bilingual explanation until the title, author,
affiliation, course, instructor, and due date are complete and the mapping is
unambiguous.

## APA renderer contract

The engine owns a pure student-title-page formatter and validator. The live
cover sheet, paged preview, and DOCX exporter consume the same structured
byline result. Presentation remains renderer-specific, but academic meaning is
shared and covered by common fixtures.

Every output follows this page sequence:

1. Student title page.
2. Abstract on a new page, when present.
3. Body on a new page, always beginning with the paper title centered and bold.
4. Appendices and references on their existing new-page boundaries.

The inserted body title also guarantees the DOCX body page break when the first
authored block is a table, figure, list, or equation. Table cells preserve every
supported child block rather than flattening or dropping content. Level 4 and
5 run-in headings use the same rich-run path as paragraphs so citations and
marks survive export.

## Editor adaptation

At widths where the full floating toolbar does not fit, labels and the duplicate
word counter are hidden while icons, tooltips, and accessible names remain.
This preserves every action at the configured 1,200 px default and 900 px
minimum window without introducing a new overflow menu or changing toolbar
docking behavior.

## Updates and release notes

The existing Tauri updater remains the update mechanism. It checks the public
GitHub Releases `latest.json`, downloads the minisign-verified updater bundle,
installs it, and relaunches the app.

After installation succeeds and before relaunch, the app stores the offered
version and `Update.body`. On the next launch it compares that pending version
with the running application version. A match opens a bilingual “What’s new”
modal. Dismissing the modal clears the marker so the notes appear once. A
mismatch is retained for the next launch; malformed or empty data is discarded
without delaying startup.

The versioned section in `CHANGELOG.md` is the single release-note source. A
small tested script extracts that section for the GitHub release body;
`tauri-action` then places the same notes in `latest.json`.

## Distribution

The tag workflow builds only a universal macOS application and DMG. The public
release stays draft until manual inspection. It also produces the signed Tauri
updater archive, signature, and `latest.json`. Apple notarization remains
deferred, but the app receives a valid ad-hoc signature so downloaded Apple
Silicon builds are not treated as damaged. Gatekeeper instructions remain in
the README because the developer identity is not notarized.

A separate workflow triggered by pushes to `main` builds:

- universal macOS DMG;
- Windows MSI and NSIS installer;
- Linux AppImage and Debian package.

These packages are retained only as GitHub Actions artifacts for maintainers.
They do not create releases, update `latest.json`, or establish public support
for Windows or Linux.

## Documentation

The final README is user-facing and accurate. It leads with a stable direct
link to the latest universal DMG, explains installation and Gatekeeper, states
that v0.1.0 supports student papers on macOS, describes local-first storage and
the update flow, and provides source-build instructions. Professional-paper,
Windows, Linux, obsolete roadmap, stale test-count, and wrong-repository claims
are removed or clearly labeled as future work.

## Release gates

The release is publishable only when all of the following are true:

- repository verification is green: check, 396+ tests, format, and lint;
- preview and DOCX golden tests cover the body title, page boundaries, group
  title pages, table-cell blocks, and run-in-heading citations;
- the toolbar fits at 900 px and 1,200 px with all actions usable;
- updater secrets exist and match the configured public key;
- the repository or release host is public;
- the main-branch artifact matrix succeeds on macOS, Windows, and Linux;
- the draft macOS release contains a mounted, launchable universal DMG plus a
  valid updater manifest and signature;
- the README download link resolves after publication.

No Mac App Store submission, Apple notarization, public Windows/Linux release,
professional-paper support, schema-version bump, or unrelated UX redesign is
part of v0.1.0.
