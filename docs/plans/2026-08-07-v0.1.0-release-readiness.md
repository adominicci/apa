# Tesina v0.1.0 Release Readiness Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver an academically trustworthy APA 7 student-paper release as a public universal macOS DMG, with a working signed updater, restart-time release notes, and maintainer-only Windows/Linux CI artifacts.

**Architecture:** Keep essay schema version `2` and centralize student title-page validation and byline mapping in the pure APA engine. Apply every document fix symmetrically to the cover, preview, and DOCX paths, then keep packaging CI separate from the public macOS tag workflow. `CHANGELOG.md` is the canonical source for both GitHub and in-app release notes.

**Tech Stack:** Deno 2, TypeScript, Svelte 5, TipTap 3, Vitest, Tauri 2, Rust, `docx`, GitHub Actions, `tauri-action`.

---

## Implementation conventions

- Work in a dedicated worktree on `features/v0.1.0-release`.

- Use `@svelte-code-writer` and its autofixer for every touched `.svelte` file.
- Never bump `essay.schemaVersion` from `2`.
- Never print updater private keys or repository secret values.
- Run the four root verification commands after every task-sized commit.
