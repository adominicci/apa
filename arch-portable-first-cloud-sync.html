Tesina portability strategy

Portable first.
Cloud when useful.

Build one trustworthy way to move everything, then let optional cloud sync reuse the same data contract. Users keep ownership; Tesina avoids two incompatible storage systems.

✓
The archive is the foundation, not a temporary workaround. Manual transfer and cloud sync both move the same essays, references, images, settings, and format version.

Three delivery stages

Export or import one complete library

Tesina creates a single archive such as My Tesina Library.tesina. Moving to another Mac or Windows PC becomes: export, copy, import.

  • Works offline and without creating an account.
  • Validates the archive before changing local data.
  • Merges without silently replacing the local library.
Immediate value Migration, backup, and user ownership

This fixes the urgent problem with the smallest operational burden.

Store validated versions in a synced folder

Tesina writes the same logical archive to a user-selected folder. Google Drive, iCloud Drive, OneDrive, or Dropbox can sync it without a Tesina account.

  • One daily snapshot when library content changed.
  • Restore any device through the same safe Merge preview.
  • Keep seven recent versions to recover from mistakes.
Added value Off-device disaster recovery

A stolen or failed computer no longer takes the entire library with it.

Sync individual changes safely

Once backup is reliable, Tesina can exchange versioned essays and assets instead of repeatedly replacing the whole library.

  • Each essay carries a revision and modification history.
  • Non-overlapping edits merge automatically.
  • Conflicting edits produce two recoverable copies—never silent data loss.
Long-term value Continue writing on another device

This is the most complex stage, added only after export and restore are proven.

Suggested file contract

What is inside a `.tesina` archive?

A ZIP container can remain transparent and portable while the manifest gives Tesina strict validation and future migrations.

Click each row to see why it exists.

manifest.json
Records the archive version, creation time, app version, file checksums, and optional encryption metadata.
essays/<id>.json
Keeps each essay independently identifiable so imports and future sync can merge instead of blindly replacing everything.
assets/<id>.<ext>
Makes figures portable. References in essay JSON are rewritten or resolved through stable asset identifiers.
library.json
Moves the shared bibliography and collections while essay snapshots protect citations during reconciliation.

Non-negotiable guardrails

What makes this trustworthy
Validate before writing Read and verify the entire package in temporary storage before changing the user’s live library.
Never silently overwrite Duplicates and conflicts receive clear choices and retain recoverable copies.
Cloud stays optional Export/import continues working forever, even if the user never signs in or a service disappears.
Recommended first milestone: full-library export/import with manifest validation, asset inclusion, merge preview, and automatic pre-import backup. Cloud backup comes after that round trip is proven.
